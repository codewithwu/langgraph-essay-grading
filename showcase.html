作文
评分智能体

基于 LangGraph 的多维度评分系统。两种评分模式：标准模式 4 维（审题立意 · 论据分析 · 结构评估 · 语言文采），高考模式 7 维——完整对齐 w.md 中的「基础等级 + 发展等级 + 扣分细则」。条件短路精准识别跑题卷， 纯前端 SPA 部署于 GitHub Pages，以墨韵为骨，以工程为魂。

A multi-agent essay grading system built on the LangGraph state-machine — two scoring modes (standard 4-dim / gaokao 7-dim), pure front-end, deployed to the open web, designed in the spirit of rice paper and vermillion seals.

02
ESSENCE / 项目摘要

这是一个把"多智能体工作流"塞进浏览器的小型工程。 用户粘一篇高考作文、敲一下回车，前端 SPA 便会驱动一组由 LangGraph 编排的智能体—— 先由审题节点判定"是否切题"，再决定要不要并行启动三路（标准）或六路（高考）评估节点； 评分通过 OpenAI 兼容协议以 HTTPS 直连大模型，没有后端、没有代理，Key 只活在 localStorage。

顶部首页可一键切换 标准模式 / 高考模式：前者用 4 维通用打分，后者展开为 7 维并对齐 w.md 评分标准（基础等级 + 发展等级 + 扣分细则）。整个项目用 TypeScript + React 18 + Vite 写成，由 GitHub Actions 自动构建并发布到 GitHub Pages。UI 取"墨韵"之意——宣纸为底、墨黑为文、朱砂为印；评分卡用盖印式印章 收束，每个维度依次流式上屏。

适合作为多智能体编排、前端 AI 应用、纯静态部署三个方向的参考实现—— 它足够小，可以一晚上读完；也足够完整，覆盖了状态机设计、流式渲染、跨域 LLM 调用、CI/CD 等真实工程问题。

03 / 核心亮点

六个让人会心一笑的工程巧思

项目体量很轻，但每一个"看起来理所当然"的功能背后，都藏着一个具体的设计取舍。 下面六点，是它最值得展开讲讲的地方。

HIGHLIGHTS SIX FEATURES 2026
01 / Conditional Short-Circuit

条件短路机制

Off-topic essays are not over-graded.

审题立意 ≤ 0.5 的作文会被直接送往综合分节点，跳过论据 / 结构 / 语言三路评估。 跑题卷不会被"凑维度分"——这是把阅卷伦理写进状态机的体现。 标准 / 高考两套图复用同一条条件边。

02 / Parallel Fan-Out

多路并行评估

Standard: 3-way · Gaokao: 6-way.

审题通过后，fan_out 节点把状态同时分发给多路评估节点。 标准模式三路并行、高考模式六路并行（内容/结构/语言/深度/创新/卷面）， 耗时由"加和"压缩为"取最大"。

03 / Streaming UI

流式评分体验

Cards reveal as soon as a node finishes.

LangGraph 事件流通过 useGradingStream 逐事件下发， 前端用 useEffect 增量上屏——用户先看到"审题 0.82"， 再依次看到论据、结构、综合分，不需等待全部完成。

04 / Pure Front-End / No Backend

纯前端 · 零后端

API Key never leaves the browser.

默认配置外置到 llm-defaults.json， 用户覆盖值存于 localStorage，构建产物只有 dist/，可以直接 actions/deploy-pages。

05 / Gaokao 7-Dim Mode

高考模式 · 七维度

Aligned with the official 高考 grading rubric.

切换到高考模式后，工作流展开为 7 个并行维度： 审题立意 / 内容论据 / 篇章结构 / 语言文采 / 思想深度 / 创新创意 / 卷面格式—— 对齐 w.md 中的「基础等级 + 发展等级 + 扣分细则」，并以 1/7 等权加权。

06 / Header · Seal & Repo

顶部 Header · 朱砂印章 + 仓库直达

A seal and a one-click route to the repo.

顶部 Header 在 QR 码旁新加「仓」字朱砂印章 + 「仓库地址」链接—— URL 隐藏在 href，点击直达 GitHub。 与 H1 旁的「墨」字印章呼应，整套设计语言在工程中复用。

06 / 三大工程亮点

把"小项目"做出"系统感"

任何一个维度展开，都够写一篇小博客。下面这三个，是我觉得最值得展开的。

审
relevance > 0.5
relevance ≤ 0.5

条件短路 —
让跑题卷"该低就低"

Ethics encoded in the state machine.

在 routes.ts 里只有 6 行代码：判断 relevance.score 是否大于阈值 RELEVANCE_THRESHOLD = 0.5，决定走 fan-out 还是直达 final。

这条条件边的存在，让工作流具备一个非常拟人化的能力—— 它"知道"自己不该对一份严重跑题的卷子在论据和语言上继续扣分。 这不是性能优化，是评分伦理的工程化。

  • 阈值集中管理：调整 RELEVANCE_THRESHOLD 即可改变闸口松紧，routes.test.ts 全覆盖。
  • 权重独立：四个维度的权重也集中在 config.ts，调参不需要改任何业务代码。
  • 状态兼容：短路时 evidence/structure/expression 留空，calculate_final_score 用 ?? 0 安全降级。

三路并行 —
让等待时间取最大值

From O(sum) to O(max) in latency.

fan_out 是一个空操作节点，但它的三条出边是同时激活的： check_evidence / check_structure / check_expression。

LangGraph 会在所有入边都就绪后才触发 calculate_final_score， 三路 LLM 调用因此从"串行加和"压缩为"取最大值"。在前端表现上， useGradingStream 可以监听到事件交错到达——而不是苦等最慢那一路。

  • 事件流：每个节点完成都广播一次事件，useGradingStream 累积到 React 状态。
  • Zod 强类型：ScoreDetail = z.object({ score, reason })，编译期就能拿到结构。
  • 提示词分离：每个维度的指令集中在 DIM_INSTRUCTIONS，调提示词不用碰业务代码。

流式上屏 —
让用户在等待中"看见进度"

Cards reveal, then seal, then stamp.

评分过程中，前端会先把"审题立意"卡片显示出来（带骨架过渡）， 三路并行结果按到达顺序依次展开，最后由盖印动画呈上"综合分"印章。

体验上像是"老师在批卷时把分数先念出来，最后才盖章"—— 比起"黑屏等待 5 秒再整体出现"，流式让用户始终在信息流里。

  • 动效一致：墨滴落入、卡片 stagger reveal、印章盖下弹跳——全是 CSS 关键帧，无重型动画库。
  • 朱砂主题：自研滚动条、选区配色、按钮 hover 流光——所有动效共享同一组 CSS 变量。
  • 可降级：当 prefers-reduced-motion 启用时，动画自动收敛为淡入。
07 / 设计语言

墨韵 — 把中式编辑美学写进工程

整套 UI 不靠渐变与玻璃拟态撑场面，而是回到宣纸 · 墨 · 朱砂三原色。 字体用 Noto Serif SC 作正文、Ma Shan Zheng 作印章字、Inter 作数字英文—— 让 AI 评分结果第一次有一种"被老师用红笔批过"的样子。

字是设计的主角

Typography is the protagonist.

整个项目没有引入任何 Tailwind / shadcn / Material。 所有视觉规则都在 src/styles/ 里以原生 CSS 写就—— 字号、字重、字距、字号比都有自己的节奏。

中文标题用 Noto Serif SC（思源宋体）的 700/900； 印章字符用 Ma Shan Zheng（马善政书法体），可读性无所谓，气质说了算； 拉丁字符用 Cormorant Garamond，让"ESSAY GRADING"这种小标有杂志感。

评分卡有"序号徽章"、综合分用"盖印式印章"——动效是盖下时的微抖动， 配合颗粒噪点模拟"印泥"质感，让 AI 评分第一次看起来不像在写代码。
